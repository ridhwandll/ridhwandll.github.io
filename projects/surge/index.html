SURGE

Mobile-first 2D / 3D game engine

Surge Engine. Surge is my game engine.
It runs on phones first, and looks even better on a PC.

I started it in 2021, after my first engine, Spike. It's C++20 on Vulkan 1.1, with Jolt physics, Lua scripting and its own editor. Android is the main target, so everything has to fit a phone's heat, battery and memory budget first. On desktop it can afford heavier shadows, GTAO and a lot more lights.

BUDGET

Phones first

If a feature can't be cheap on a phone, it doesn't go in. Desktop-only extras (more shadow cascades, GTAO, more lights) are optional and never make the Android path slower. In practice: fewer draw calls, fewer render passes, tile-friendly load/store ops, and no allocations every frame.

Platform defaults straight from FrameBlackboard.hpp. Every value is editable live in the Editor's Renderer panel, with Mobile/Desktop preset buttons.

Batched, non-blocking uploads

Buffer and image data go through a recycled staging ring into one upload command buffer, submitted right before the frame. No one-time submits, no vkQueueWaitIdle.

Frame pacing on Android

Swappy presents on vsync at a target rate, so a 120 Hz phone doesn't burn its battery rendering 120 frames nobody asked for.

Render scale

The 3D scene renders at 0.5–1.0×, UI and post-processing stay at native resolution. 0.8 on Android, 1.0 on desktop.

Persistent pipeline cache

A VkPipelineCache saved to device storage and header-validated against the current GPU and driver. Warm starts skip pipeline compilation.

The render graph

Each pass says what it reads and writes, and RenderGraph::Compile() sorts them and works out the barriers and load/store ops. Culling and uploads happen in Prepare, before any render pass starts. If a whole group has nothing to draw it's skipped: no begin, no clear, no store. On mobile GPUs that's real bandwidth saved.

▾RendererSettingsGraphStats
Has work Skipped: no begin / clear / store Manages own execution

Click a group to toggle whether it has work this frame.

  1. SetupCreate targets, declare image reads and writes.
  2. PrepareFrustum culling, instancing, uniform and descriptor updates, for every enabled pass.
  3. CompileSort, derive barriers and load/store ops, drop empty groups.
  4. ExecuteRecord only. Nothing allocates, nothing uploads.

What's in it

Rendering

Thin, handle-based RHI over Vulkan 1.1. Layouts and vertex attributes generated from SPIR-V reflection.

  • Per-submesh frustum culling + automatic instancing
  • Energy-conserving Blinn-Phong with PBR inputs, procedural Preetham sky
  • Cascaded shadows, GTAO, HDR bloom, ACES, FXAA

Particles

Up to 16 emitters per effect, built from plain-data modules. Curves and gradients baked to 64-entry LUTs.

  • Texture sheets, collision planes, sub-emitters
  • SoA pools allocated once, vertex pulling from an SSBO
  • Optional per-particle radix sort, one draw per texture run

Physics

Jolt Physics on a fixed 1/60 s step with render interpolation.

  • Box, sphere, capsule, cylinder, convex hull, triangle mesh
  • Sensors, CCD, rotation locks, raycasts
  • Contact and trigger events delivered to Lua

Lua scripting

Lua 5.4 + sol2, compiled to bytecode at cook time, sandboxed, full tracebacks.

  • Multiple scripts per entity, each in its own environment
  • require modules that work the same on Android
  • Inspector properties with zero per-frame cost

Game UI

A retained widget tree with Unity-style rect transforms and a canvas scaler.

  • 18 widgets: joystick, recycling ListView, InputField, modals…
  • Sprites and MSDF text share one shader and pipeline
  • CPU clipping keeps batches intact, multi-touch per pointer

Assets & cooking

Every asset has a stable UUID; the runtime only ever loads cooked binary data.

  • Textures to UASTC, transcoded to ASTC / ETC2 / BC7
  • meshoptimizer'd glTF, MSDF font atlases, Lua bytecode
  • Stale assets re-cook automatically in the Editor

Audio

miniaudio, played from memory. Streamed clips decode as they play, the rest decode once and share PCM.

  • 3D spatialized sources and a listener
  • Inverse, linear or exponential attenuation

Input

Keyboard, mouse, multi-touch with stable small IDs, and gamepads (XInput on Windows, joystick events on Android).

  • Touch-synthesized mouse events never double-handle a tap
  • Android Back maps to Escape

ECS & scenes

EnTT-backed scenes, hierarchies, deferred destruction and frame-end callbacks.

  • Readable JSON for the Editor, reflection-driven binary at runtime
  • A schema hash re-cooks scenes when a component changes

Lua scripting

Scripts declare Properties that show up in the Inspector as typed fields. Values are saved sparsely per entity and written once before OnCreate, so they cost nothing per frame.

  • OnCreate, OnEnable, OnFixedUpdate, OnUpdate, OnLateUpdate, OnDestroy
  • Collision and trigger callbacks straight from Jolt
  • Physics.Raycast, Particles.Play, Scene.Load, Time.*, Storage.*
  • Full VS Code IntelliSense ships in SurgeAPI.lua

The Editor

Unity-style Scene views (as many as you want, each with its own camera and render graph), a Game view that can fake phone safe areas, undo/redo, and one-click Windows and Android builds.

ViewportsAny number of Scene views, one Game view with aspect presets and safe-area simulation.
Gizmos & pickingTranslate / rotate / scale with snapping, clickable component icons, CPU ray picking with no GPU readback.
Hierarchy & InspectorDrag-and-drop parenting, multi-script entities, Lua properties as typed fields.
Particle EditorEvery module, curve and gradient, with an isolated live preview and shape gizmos.
UI EditorWYSIWYG layout editing right in the Game view.
Material EditorEdit parameters and textures with live results.
Renderer panelQuality settings, Mobile / Desktop presets, live render graph visualizer, per-pass stats.
Content BrowserAsync thumbnails, favorites, search, drag-and-drop import that keeps the registry in sync.
ExportWindows executables and Android APK / AAB via Gradle. Install, launch and stream device logcat.

Asset cooking

Shipped games can't load a .gltf, on purpose. The Editor cooks every source file into a small binary format first, so the Player doesn't carry importers or decoders around, and it loads faster.

Building it yourself

No submodules, no package manager. Every dependency is vendored with its own CMake list.

Windows

Visual Studio with the C++ Clang (ClangCL) tools, CMake 3.20+ and the Vulkan SDK.

git clone https://github.com/ridhwandll/Surge_Expired
Scripts\WindowsGenProjects.bat
msbuild build/Surge.slnx -p:Configuration=Release

Start project: Editor. The working directory is always the repository root.

Android

One script installs the whole toolchain without Android Studio: JDK 17, SDK, NDK and CMake, pinned to what Gradle expects.

Scripts\AndroidSetup.bat

Then export an APK or AAB from the Editor's Export panel, install it on a device and watch its logcat in the Console. Vulkan 1.1 needs Android 10 (API 29) or newer.
